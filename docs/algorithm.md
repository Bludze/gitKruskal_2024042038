# 算法说明

## 1. 问题定义

给定一个带权无向连通图 `G = (V, E)`，最小生成树（Minimum Spanning Tree, MST）是 `G` 的一棵生成树，使其所有边的权重之和最小。

## 2. Kruskal 算法思想

Kruskal 算法属于贪心算法：每一步选择当前权重最小且不会与已选边构成环的边，直到选满 `|V| - 1` 条边。

### 2.1 算法步骤

1. 将图中所有边按权重升序排序
2. 初始化并查集，每个顶点自成一个集合
3. 依次取出排序后的每条边 `(u, v, w)`：
   - 若 `find(u) != find(v)`，说明加入该边不会成环，选中该边并 `union(u, v)`
   - 否则跳过该边
4. 当已选边数达到 `|V| - 1` 时结束；若遍历完所有边仍不足，则图不连通

### 2.2 伪代码

```
KRUSKAL(G):
    A = ∅
    for each vertex v in G.V:
        MAKE-SET(v)
    sort G.E by weight ascending
    for each edge (u, v) in G.E:
        if FIND-SET(u) ≠ FIND-SET(v):
            A = A ∪ {(u, v)}
            UNION(u, v)
    return A
```

## 3. 并查集优化

- **路径压缩（Path Compression）**：`find` 时把路径上的节点直接挂到根节点，后续查询接近 `O(1)`
- **按秩合并（Union by Rank）**：合并时把秩小的树挂到秩大的树下，控制树高

两者结合后，单次操作的均摊复杂度为 `O(α(n))`，其中 `α` 为反阿克曼函数，实际可视为常数。

## 4. 复杂度分析

| 阶段 | 复杂度 |
| --- | --- |
| 边排序 | `O(E log E)` |
| 并查集初始化 | `O(V)` |
| 遍历边 + 并查集操作 | `O(E α(V))` |
| 总计 | `O(E log E)` |
| 空间 | `O(V + E)` |

由于 `E ≤ V²`，也可写作 `O(E log V)`，但在稀疏图上排序仍是主要开销。

## 5. 正确性说明（贪心选择性质）

设当前最小权重边为 `e = (u, v)`，若 `e` 不在某棵最小生成树 `T` 中，则 `T + e` 构成一个环。环上必有一条与 `e` 权重不小于 `e` 的边 `e'`（否则 `T` 不是最小的）。用 `e` 替换 `e'` 得到另一棵生成树，权重不增，因此存在包含 `e` 的最小生成树。归纳可得 Kruskal 算法正确。

## 6. 与 Prim 算法对比

| 维度 | Kruskal | Prim |
| --- | --- | --- |
| 策略 | 按边贪心，全局排序 | 按点扩展，维护候选边 |
| 适用图 | 稀疏图更优 | 稠密图更优 |
| 数据结构 | 并查集 | 优先队列 |
| 复杂度 | `O(E log E)` | `O(E log V)`（二叉堆） |
| 并行性 | 天然适合并行选边 | 顺序扩展，较难并行 |

本项目的图形界面选择 Kruskal，是因为「边排序 + 逐条判断成环」的过程更适合逐步动画演示，每个步骤的因果清晰可见。
